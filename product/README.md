Прототип спецтрека ЛЦТ: работодатель открывает категорию людей с записанным грейдом и профилем достижений Федерации спортивного программирования, затем сам шлёт приглашение с вилкой в рублях.

Авторы: Чистяков Евгений, Иван Курлыков, Леонид Пластуненко, Николай Кузнецов, Игорь Софронов.

Кабинеты соискателя и работодателя живут в одном процессе. Боевого реестра ФСП на стенде нет: JSON из git при старте попадает в SQLite, кабинеты читают таблицы.

## Быстрый старт

На машине заранее стоят только Docker Engine и плагин Compose. Язык, пакеты и база на хост не ставятся. Полный `up` поднимает и локальный Keycloak, в образ приложения он не ставится. Почта остаётся входом, связь ID — кнопка в кабинете. Переключение на issuer заказчика — [`deploy/fsp/keycloak.md`](../deploy/fsp/keycloak.md). Копировать `compose.env` не нужно: файл необязателен и только про секрет продукта. Если `PRODUCT_SECRET` короче 32 символов, точка входа пишет секрет в том `/data/product_secret`. Переменные OIDC — в `deploy/fsp/.env`, этого файла в git нет.

Из корня репозитория:

```text
docker compose -f deploy/fsp/compose.yaml up --build
```

| Что | Адрес |
| --- | --- |
| Кабинеты | <http://127.0.0.1:8000> |
| Консоль Keycloak | <http://127.0.0.1:8080> |
| OpenAPI, без сети | <http://127.0.0.1:8000/docs> |
| ReDoc, без сети | <http://127.0.0.1:8000/redoc> |

Вторая команда — тесты тем же образом, отдельным контейнером:

```text
docker compose -f deploy/fsp/compose.yaml --profile test run --rm tests
```

Второго способа (venv и pytest на хосте) нет. Бейдж «tests» в шапке — снимок полного прогона этой команды, не части набора: сейчас 176 passed, зелёный. Файл пишет `pytest_sessionfinish` в `docs/badges`. Частичный pytest этот файл не заменяет. Свой `PRODUCT_SECRET` можно положить в `deploy/fsp/compose.env` по образцу `compose.env.example`; файл в git не входит. Точка входа и приложение читают один контур: переменная или `PRODUCT_SECRET_FILE`.

Публичного URL нет. Кабинеты после compose — <http://127.0.0.1:8000>. Хост не выдумываем: без Docker смотрите скрины и видео презентации.

Прогон валидации — ссылка «Прогон валидации» в подборке работодателя. Один раз после четырёх шагов из [`track/lct-fsp-vacancies/demo.md`](../track/lct-fsp-vacancies/demo.md). Ответ — пять золотых строк, `grade_separation` и три строки CPU-персон (`sim_competent`, `sim_key_leak`, `sim_adjacent`); целевых процентов нет. Это CPU, без GPU. `category_match` — ожидаемая категория, `outcome_match` — итог теста, `form_stable` — тот же вариант теста и те же ответы дали тот же грейд, `relevant_in_top` — отмеченные релевантными в топе, `resume_ok` — PDF без падения. `grade_separation` — сколько вопросов каталога разделяют грейды и сколько вопросов всего; порога по этой строке нет. `sim_*` — CPU-персоны на том же тесте, что в кабинете: знает свой уровень, выучил чужой ключ по позициям, уровень на ступень ниже заявленного; порога нет. Отдельно `python -m product.matching.synth_eval_run` печатает девять строк на 1000 синтетических профилей с известным грейдом; GET остаётся золотым набором 38, график — [`docs/synth-eval.svg`](docs/synth-eval.svg).

## Как устроено

Один процесс uvicorn, один worker, один файл SQLite в режиме WAL.

- Веб: Jinja2 и локальный htmx 2.0.4. Страницы `/auth`, `/candidate`, `/employer`. Ссылок на CDN нет.
- API: FastAPI, JSON под `/api`, сессия — cookie `product_session`.
- Правила категории, теста и разбора резюме — функции в `product/matching`. Сеть им не нужна.
- Мок достижений — `product/fsp_mock` кладёт `participants.json` в SQLite при старте.

Тест грейда (`product/matching/assessment.py`): у каждого кандидата свой вариант из 12 вопросов по единому плану — 3 вопроса уровня ниже, 6 заявленного, 3 выше. Вопросы из банка семейств (216 вопросов каталога), варианты ответа перемешаны, ключ хранится только на сервере. Кандидат оценивает каждый вариант «верно / неверно». Уровень считается по IRT; у границы грейдов тест добавляет до трёх блоков вопросов. Итог — грейд, уверенность, статус «уверенно / у границы» и положение в грейде. Механика проверена симуляцией на 500 синтетических кандидатах: `python -m product.validation_sim.run`, отчёт — `validation_sim/out/report.md`.

Каталог-источник банка — `product/matching/stems.py`: 216 вопросов, по 9 на пару «специализация × грейд», темы `refusal_contract`, `close_cause`, `offline_check`.

Категория — специализация и записанный грейд, например `backend:middle`. Отрасль MVP только `it`: она видна в статусе профиля и в `category_id` не входит. Неудачный тест грейд не понижает.

Подборка работодателя — по категории или по всей базе: без категории выдаются все опубликованные профили с фильтрами по специализации, грейду, стеку, роли, формату и достижениям ФСП (`GET /api/employer/candidates`, страница `/employer/shortlist`).

Текст потребности сравнивается стемами `snowballstemmer` 3.1.1 (BSD-3-Clause), не подстрокой. Короткие слова не отбрасываются. Неполное совпадение текста карточку не выкидывает: число совпавших стемов входит в порядок выдачи. По непустому тексту над списком подсказка: основная категория и одна запасная строка соседнего грейда, у каждой число опубликованных. Категорию выбирает человек.

На опубликованном профиле три галки: ФИО, стаж, достижения ФСП. Снятая галка оставляет поле на карточке пустым. Выключенная публикация по-прежнему убирает карточку целиком.

Свою вакансию работодатель правит на той же строке. Статус остаётся `published`, чужая строка отвечает 404.

Не чаще раза в 30 дней кандидат видит одно короткое задание опубликованной вакансии. На карточке строка давности сдачи. Бонус актуальности `0` или `1` стоит после пяти чисел потребности и перед `rank_key`, не внутри строки ранга. Балл теста и грейд сдача не двигает.

Вход по паролю: после 5 неверных паролей подряд вход по этой почте закрыт на 15 минут (ответ 429 `login_locked`); счётчик ведётся и для незарегистрированных адресов.

Приглашение работодатель пишет с карточки подборки: номер профиля подставляется скрытым полем. В форме — текст, название компании, способ связи компании и вилка в рублях. Способ связи компании соискатель видит сразу. Почта соискателя появляется у работодателя только после `accepted`.

## Что сознательно не входит

Публичного URL нет. Вакансия, отклик и одно короткое задание на стенде есть. Нет живого вебхука ATS, проверки ИНН и перевода разряда в KPI. Концепция очереди модерации и снимка для ATS — в записке.
